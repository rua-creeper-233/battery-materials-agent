# 怎样把Battery Evidence Lab做成真正有工具的科研Agent

## 1. 先分清三个层次

- 关键词检索：按词或标签找到论文。
- RAG：把检索出的证据交给模型组织回答。通常是一条固定流程。
- 工具Agent：根据任务和已取得的结果选择下一步工具，取得新证据，再决定继续还是结束；必须有执行边界和可复查记录。

多Agent并不是必要条件，微调大模型也不是第一步。对当前需求，一个有证据、会拒答、工具权限有限的小Agent比复杂自动化更容易验证。

## 2. 本次实现的边界

新增本地 `/api/agent`，提供四个只读工具：查论文、取已知论文记录、查本地全文短摘录、生成方法工作流。模型配置后可依据返回结果再次选择工具，最多四次工具动作，随后结束或安全回退。页面展示工具和结果概要，不展示模型内部思维链。

工具不能执行Python/系统命令，不能打开任意路径、下载任意网址、提交VASP作业、改Zotero或推送Git。这些写入仍由用户明确授权后的维护操作完成。接口只允许本机访问，不通过公开隧道提供全文工具。

未配置模型时会标明“确定性工具流程”：工具确实执行，但下一步不是模型决定。不能把这个状态称为已接通生成式Agent。联网模型的真实效果必须用你选择的模型另外验收；离线假模型测试只能验证程序协议。

## 3. 真正启用的步骤

1. 先确认本地启动的是 `battery_materials_agent` 项目；运行 `start.bat`，查看页面的论文数量、本地连接和模型状态。默认启动端口可与旧会话不同，以窗口输出为准，不要把另一个服务当成本项目。
2. 选择本地或远程模型。模型须提供本项目兼容的聊天接口；本项目暂不负责安装模型或购买服务。GitHub Copilot/Nodus账号能用不代表它自动提供这里可用的API。
3. 双击 `start-rag.bat`，填写供应商明确提供的完整接口地址、模型名称与密钥。本地模型不需密钥时留空。密钥只在本次进程中，不要写进HTML、GitHub仓库或截图。
4. 远程模型会收到问题、选中的元数据及短摘录。先确认版权、保密和供应商数据政策；未公开课题、企业配方、私人笔记不要默认上传。需要不出机时使用可信本地模型。
5. 确认网页显示模型已配置，选择“工具Agent”。试问“帮我找聚合物电解质MD的可复现工作，比较其输入、输出和缺少的信息”。
6. 检查动作记录：是否搜索、是否读取相关证据、最终引用是否来自实际读取的条目。如果只是输出漂亮段落而没有相关证据，不能算通过。
7. 再问库中没有的问题，以及诱导执行命令的问题。应报告缺证据或拒绝工具，不编造DOI或执行命令。

`/api/chat`保留原RAG路径；GitHub Pages本身不能运行Python，也不应该保存模型密钥。公开页面可浏览元数据和教程；新的全文工具Agent仅在本机使用。导师如果只需查看页面无需本地服务器；若需要独立交互式模型服务，需要另行设计受控后端和权限，不建议直接暴露当前全文接口。

## 4. 后续怎样迭代，而不是盲目“训练”

第一步收集20–50个真实任务，标注应该找到哪些证据、哪些问题必须拒答。区分“训练/开发用题”和最终独立测试题；不要看完测试结果再修改同一测试集。

第二步改检索：加入材料名称、同义词、字段过滤、文献版本及全文章节；必要时再加入向量检索与重排序。用MRR/Recall和错误案例比较，而不是仅凭回答长度判断智能程度。

第三步改工具选择：模型是否选择合适的工具、是否重复调用、是否能发现缺失信息；限制总调用数、上下文体积、超时和单次费用。当前实现没有长期自主运行或后台科研权限。

第四步验证答案：引用编号存在只是最低条件，不证明每句都被证据支持。人工抽查“结论—页码—原句/图表”链路，记录参数错误、版本混淆、过度外推与虚假确定性。

第五步才考虑微调：积累经过研究者审核的“问题→正确工具动作→证据→答案”数据后，再评估微调是否胜过提示词/检索改进。不要用模型自动生成的错误答案反复自训练，也不要把版权全文直接作为可公开训练数据。

## 5. 验收清单

- 找得到：DOI精确检索正确，方法与体系不会混淆。
- 读得对：只有实际返回的证据能被引用；截断不会留下虚假已读记录。
- 说得清：区分论文事实、教学解释、研究设想和未知。
- 拒得住：未知工具、越权路径、文献中的恶意指令都不能产生系统动作。
- 可追溯：保留工具记录、版本、来源和测试集，不把思维链当审计日志。
- 可退回：模型失败或引用无效时明确回退，界面不能假装模型成功。

材料模拟的核心结论仍需原始计算和独立验证。Agent能帮助查证、组织输入与审查流程，不能替代DFT/MD物理验证或导师对课题创新性的判断。
