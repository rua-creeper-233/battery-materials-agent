## 仍需改善的地方

### 高优先级

1. **混合检索**：当前主检索是可解释的字段加权和 TF-IDF；下一步应加入 BM25，并在本地可用时增加小型向量模型/重排序器。关键词命中仍不能等同于语义相关。
2. **全文覆盖**：目前全文页级证据只覆盖已合法保存并通过 PDF 审计的论文；其余论文只能作为 DOI/摘要入口，不能生成原文参数。
3. **参数级证据**：数值守卫是保守的字符串检查，不是物理量解析器。今后应把参数、单位、页码、图表和适用体系结构化，并支持单位换算后的等价值。
4. **人工评测集**：增加导师/组会实际问题，分别评估文献定位、方法识别、复现步骤、数值抽取、比较和拒答；训练集与评测集必须按论文分组隔离。
5. **模型与 RAG 分工**：小模型只学习回答格式、工具选择和拒答习惯；论文事实始终来自 RAG。不能用模型记忆替代 DOI、页码和原文核对。

### 中优先级

- 为每篇记录维护 DOI 版本、出版社、开放获取状态、全文审计时间和 Zotero 条目状态。
- 对上传、索引、Zotero 写入增加可恢复的事务日志；失败时支持从最后一篇继续，而不是重复创建。
- 公开 GitHub Pages 只放元数据、教程和检索界面；本地 PDF、Zotero 链接、模型密钥和上传内容继续保持回环访问。
- 增加检索失败、引用无效、模型超时和 GPU OOM 的可见诊断，不把回退回答伪装成生成式模型回答。

## RTX 3060 6 GB 的建议闭环

1. 先运行 `python training/train_qlora.py --dry-run`，确认训练集只读取 `split=train`，验证集保持独立。
2. 在 WSL2 或兼容的 CUDA Python 环境中先训练 Qwen3-0.6B；若显存不足，依次把 `max_seq_length` 调到 512、LoRA rank 调到 8。
3. 用 `training/evaluate_model.py` 对固定 `eval.jsonl` 评估引用率、格式率和拒答率；不要只看 loss。
4. 将训练后模型作为“回答组织器”，继续由本地论文检索、全文页码和数值守卫提供事实边界。
5. 只有在 0.6B 闭环稳定后，再试 Qwen3-1.7B；不建议在 6 GB 显存上做全参数训练或 4B 以上 QLoRA。

## 质量门槛

- DOI 唯一、可解析且与标题匹配。
- 论文标签有字段依据，不因引用某软件就推断论文实际使用该软件。
- 具体计算参数必须能回到证据页、图、表或补充材料。
- 全文缺失时明确说“当前库只有元数据/摘要”。
- 模型输出失败时回退到可验证的确定性流程，并记录原因。
